# PromptForge 第二阶段执行计划

## 1. 目标、已确定方案与代理分工

依据现有第二阶段 spec，完成“体验案例 → 生成或编辑 → 校验 → 确认应用 → 保存 → 重新打开或恢复”的 React 工作闭环。

本计划采用以下决策：

- 使用 IndexedDB 保存本地项目，提供手动保存和未保存提示；不做云同步、自动保存。
- 一个项目对应一个主会话。新建项目进入空白主会话；打开项目恢复该项目已保存的 `Project.messages`、当前文件、已接受版本和必要运行摘要，然后在同一项目会话中继续聊天。不新增通用多会话/线程架构。
- 普通界面不提供“首次生成”或“基于当前代码修改”的日常模式开关；内部仍必须明确判定 `generate`、`edit`、`chat`。空项目生成，有代码且用户明确要求修改时编辑，解释/讨论只走聊天且不创建候选或版本，意图有歧义时先询问，不能默认覆盖当前文件。
- 已有会话中提出“另一个项目”时，先确认创建独立项目主会话；可带入用户选择的背景消息或需求摘要，但不混用原项目的文件、工作副本或版本身份。
- AI 修改以当前编辑器文件为基线，结果先进入候选区，通过校验后由用户确认应用。
- 发送修改请求时以当前编辑器的完整快照（包括未保存编辑）和稳定 hash 为代码真相；历史消息只作辅助上下文。编辑请求默认只使用最近 6 条 `Project.messages`，不声称模型拥有完整会话记忆，超出窗口的组织方式保持有界并可追溯。
- 固定任务看板使用单元/集成检查或用户人工确认；Playwright E2E 不再作为当前门槛。任意生成项目做基础代码与运行检查，具体业务功能由用户确认。
- 历史版本恢复保护未保存编辑，保留后续版本。
- 项目列表提供重命名和删除入口。删除必须明确覆盖本地文件、消息、版本、候选、运行/验证摘要及关联记录；未保存、进行中生成/写入/验证/修复、存在候选或其他标签页占用时先阻止误删，已完成且不再写入的预览不单独阻断。删除事务失败时保留列表项和工作副本；当前项目成功删除后回到空白入口，旧标签页不得静默写回复活已删除项目。
- 顶部持续显示项目名、已接受版本（没有版本时显示“尚无已接受版本”，不显示 v0）和保存状态；版本号自动递增，名称/备注可选，用户输入的 `1.0.0` 只能作为标签，不能改变版本 ID 或顺序。历史版本卡片与当前版本、未接受工作副本明确区分；确认恢复 v2 在已有 v4 后直接形成新的 v5 来源记录并保留后续历史，恢复后仍需手动保存，手改/保存工作副本不虚构额外已接受版本。
- 任务运行数据默认使用固定初始数据，不承诺通用沙盒内存恢复。
- 原生 ZIP 下载和第五类 IndexedDB 故障场景由用户手动完成；代理不因这两项阻塞，证据仍标为未验证，直到用户提供现场结果。
- Vue 只形成后续评估文档，本阶段不实现。

**全部代码、脚本和文档修改交给 Luna 子代理。** 创建时必须显式传入：

```text
model: gpt-5.6-luna
reasoning_effort: max
fork_turns: "1"
```

每次任务说明包含目标、相关模块、允许修改范围、约束、验收标准，并明确“你已经是子代理，不得继续创建子代理”。

主代理负责现状核查、方案调整、关键 diff 审查、运行检查及浏览器验收，不直接修改代码。默认使用一个实现子代理逐阶段工作；只有文件范围明确独立时才增加第二个。如果模型或推理强度无法指定，报告限制，不替换模型。

## 2. 分阶段执行任务

### 阶段 A：修复案例资源与预览反馈，准备真实生成脚本

**交给 Luna 的范围：** 案例组装、预览组件、资源导出、案例生成脚本。

具体改动：

- 建立统一案例资源清单，让首页案例、Sandpack 和导出项目使用一致的资源来源。
- 固定预置案例的远程封面 allowlist，宿主检查外链可用性；manifest 记录外部 URL，导出不伪造或下载远程图片，外链失败时显示具体原因。
- 首次加载时在预览中央显示加载图标和说明，覆盖动态组件加载、模板加载与沙盒启动。
- 监听当前安装版本 Sandpack 的构建完成和错误事件；不能用 `status=running` 或 iframe `load` 单独判断应用就绪。
- 将构建成功、应用挂载反馈和运行错误分开记录；反馈桥接代码只注入预览副本，不混入用户源码或导出包。
- 首次启动使用中央提示；已有画面重新编译时保留内容，使用轻量更新提示。
- 默认等待 30 秒后提示“启动耗时较长”，120 秒后标为预览超时；两者均为可配置阈值，不是预计耗时，不自动重试。
- 提供真实生成脚本，读取固定需求，通过现有后端调用模型，保存原始事件、文件、配置摘要和终态；不记录密钥。

**验收：**

- 网络可用时首页和工作台加载六个固定远程封面；导出项目保留可审查 URL 元数据，不承诺离线可用。
- 加载、就绪、编译错误和外部超时可明确区分。
- 重试不刷新整个工作台，不丢输入或当前文件。
- 保留已有 `/workspace` 和小说案例链接。
- 生成脚本能拒绝将强制 Mock 结果记为真实案例。

### 阶段 B：项目保存、重新打开与历史恢复

**交给 Luna 的范围：** 项目数据层、工作台状态、项目列表、保存与版本界面。

具体改动：

- 增加项目仓储层，使用 IndexedDB 的事务保存项目、工作副本、版本、资源和运行摘要。
- Zustand 保留界面状态；持久化使用明确的可序列化数据，不直接保存包含 ReactNode 的展示对象。
- 提供“保存”“打开项目”“另存为”和历史版本入口。
- 工作副本与已接受版本分开：用户编辑可保存，不因此被标为已通过验证。
- 保存成功后记录快照 hash 和写入修订号；失败保留内存内容并显示未保存。
- 项目切换和历史恢复遇到未保存编辑时，提供保存、放弃、取消；冲突时可另存。
- 用户确认恢复旧版本时直接创建新的恢复版本和工作副本，不修改旧快照、不删除后续版本；恢复版本沿用被选快照，不伪造新的运行校验通过证据。
- 多标签页保存使用事务内修订号比较；冲突时阻止覆盖，不做自动合并。
- 首版数据库使用版本化 schema；不兼容或损坏数据明确报错，不静默重置。

**验收：**

- 手改标题后保存，刷新及重新打开后文件内容一致。
- 能恢复较早版本，后续版本仍可访问。
- 配额不足、写入失败、损坏记录和双标签页冲突不覆盖当前编辑。
- 本地无项目时不擅自声称用户清除了数据。

### 阶段 C：基于当前代码继续修改与候选隔离

**交给 Luna 的范围：** 请求契约、后端修改流程、文件差异、候选状态和确认应用界面。

具体改动：

- 保留现有首次生成、普通聊天和阶段 C 已实现的显式 `operation=edit` 契约，避免修改请求重新走整条首次生成链路；F1 已在普通入口增加内部自动判定，但不把该新交互倒写成阶段 C 的历史证据。
- F1 保留后端的生成和普通聊天能力，并由内部操作判定选择流程，普通界面不要求用户切换“首次生成/基于当前代码修改”；空项目进入 `generate`，有代码且明确修改进入 `edit`，讨论进入 `chat`，歧义先询问。F1 fixture、tsc、lint/build 已通过，真实聊天链路仍未验证。
- 请求冻结当前文件、资源引用、需求、项目身份及基线 hash；不以最近生成文件替代编辑器内容。
- 新增小范围编辑流程：分析修改需求 → 生成结构化文件变更 → 检查并组装候选。
- 模型返回新增、修改、删除文件操作；服务端基于请求快照合并，未涉及文件保持原样。
- 界面展示候选差异、验证结果和“应用修改／放弃候选”。
- 首次生成也进入候选状态；收到 `files + done` 仅表示完整候选已收到。
- 候选使用独立预览副本，不能写回当前编辑器。
- 应用前重新核对当前工作副本 hash。生成期间发生编辑时，候选进入冲突状态，允许查看差异或基于最新内容重新请求。
- 用户确认应用后创建不可变版本并更新工作副本；仍需手动保存到本地。
- 重试产生新运行记录，保留原始请求；取消后忽略迟到结果，不宣称上游模型已经完全终止。

**验收：**

- 手改标题后增加优先级筛选，标题及原有新增、编辑、状态切换、关键词筛选功能保留。
- 失败、EOF、取消和过期候选均不会覆盖当前内容。
- 普通聊天不产生项目版本。
- 未验证候选不能通过“应用修改”绕过校验。

### 阶段 D：分层校验与有限修复

**交给 Luna 的范围：** 验证报告、预览诊断、修复流程、固定案例测试工具。

具体改动：

- 按 spec 实现协议、源码、构建、运行和功能确认的独立结果。
- 使用 Sandpack 的真实编译结果进行在线构建检查；类型检查与导出构建由固定验证脚本单独记录，不能互相冒充。
- 固定任务看板用单元/集成检查或用户人工确认验证交互；任意项目在基础检查通过后，由用户确认业务功能，报告明确标注人工确认。Playwright E2E 可作为可选辅助，不是当前门槛。
- 自动化测试使用已审查的固定模板和测试环境；不在公共后端直接执行模型生成的 shell 命令或 package scripts。
- 提供“尝试修复”入口，用户触发后最多进行两轮自动修复，总预算默认 10 分钟，每轮验证默认最长 120 秒。
- 修复只操作候选，携带当前候选文件和明确诊断；每次修改重新验证。
- 网络不可用、供应商限流、存储失败和基线冲突不触发代码修复。
- 相同错误及相同输出重复出现时提前停止；达到边界后保留候选、错误和人工处理入口。

**验收：**

- 构造语法错误、导入缺失、运行异常及功能回归，验证分类与处理。
- 修复成功必须有重新验证的证据。
- 修复超限或环境阻断时停止，不覆盖工作副本。
- 用户确认、自动测试、未验证和跳过在报告中可区分。

### 阶段 E：固化独立任务看板与评测

**交给 Luna 的范围：** 独立案例、来源记录、固定评测需求、报告脚本。

具体改动：

- 使用 spec 中 EVAL-01 的固定需求真实生成任务看板；初版有优先级字段，但不包含优先级筛选，为 EVAL-02 保留增量任务。
- 新案例拥有独立 ID、入口、源码、资源及 manifest；继续保留小说案例及其原有来源说明。
- 保留原始输出和最终演示结果，逐项记录人工修正；不修改原始记录以掩盖失败。
- 真实生成未完成或未通过验收前，不把任务看板展示为可用案例。
- EVAL-01 和 EVAL-02 默认各运行三次，串行执行；EVAL-03 使用故障夹具，单独统计。单次探测只能作为已记录样本，不能据此形成三次成功率。
- 报告样本数量、原始成功、修复后成功、功能保留、耗时及失败原因；取消、环境阻断和未验证不从统计中消失。
- 补充 Vue 后续评估，说明模板、生成、运行和测试成本，不添加框架选择器。

**验收：**

- 两个独立项目均能直接打开和操作，不要求访客实时生成。
- 完成“手改标题 → 保存重开 → 增加筛选 → 验证 → 应用 → 恢复旧版本”完整场景。
- 来源记录能对应实际运行和最终案例。
- 样本量不足时照实报告，不宣称形成稳定成功率。

### 阶段 F：项目主会话、项目管理与版本体验（F1/F2/F3 已实现，现场未完整验证）

阶段 F 建立在 A–E 已有的项目仓储、`Project.messages`、当前编辑器文件、候选和版本机制上。F1/F2/F3 已按本节目标落到代码，并有对应 fixture、前端 tsc、lint/build 检查；完整浏览器现场、真实聊天链路、移动端/键盘、ZIP 和 IndexedDB 第五类故障仍需人工验收，不改变 A–E 的历史运行或验收证据。

#### F1：会话入口与路由上下文

**涉及现有模块：** `Project`/项目仓储、项目列表和工作台路由、`Project.messages`、`chatStore`、`useChat`、`sandpackStore`、现有请求分类与变更契约。

**实现范围：**

- 将 `projectId` 作为工作台和主会话的唯一上下文；新建项目创建空白消息、文件和版本集合，打开项目恢复已保存消息、当前文件、版本和必要运行摘要。
- 复用现有 `Project.messages` 作为主会话记录，不引入通用 `Session`/thread 表、跨项目消息池或云端会话同步。
- 移除普通 UI 的首次生成/当前代码修改开关。内部分类规则固定为：空文件 map 的新需求走 `generate`；存在代码且明确修改走 `edit`；解释和讨论走 `chat`，不产生候选或版本；无法判断时先返回澄清，不覆盖文件。
- 已有主会话要求新项目时先确认，创建独立项目上下文；只复制用户选择的背景消息/需求摘要，文件、工作副本、候选和版本仍按项目隔离。
- 修改请求冻结发送时编辑器中的完整文件 map（含未保存内容）、资源摘要和 hash；完整消息仍保存，但 edit 默认只将最近 6 条消息作为上下文，不宣称具有完整历史记忆。超出窗口的背景只有在用户选择或明确生成的摘要进入请求时才可使用。

**依赖与验收：** 依赖现有本地仓储和请求流，不新增通用多会话基础设施；对应 `R-SESSION-01`～`R-SESSION-03`、`R-CONTEXT-01`，验收条目为 `A-SESSION-01`～`A-SESSION-03`，固定场景为 `UX-SESSION-01`～`UX-SESSION-03`。F1 fixture、tsc、lint/build 已通过；真实聊天和完整浏览器现场未验证。

#### F2：项目列表、重命名、删除与迁移兼容

**涉及现有模块：** `ProjectManager`、`projectRepository`、项目列表/工作台切换、IndexedDB schema 和事务、dirty/运行中/候选状态以及多标签页修订检查。

**实现范围：**

- 项目列表为每个项目提供重命名和删除入口；重命名只更新元数据，不改变 `projectId`、文件、消息或版本身份。
- 删除前显示明确范围并检查 dirty 工作副本、进行中的生成/写入/验证/修复、未接受候选和其他标签页占用；任一条件未解决时阻止删除或要求用户先完成明确的保存/取消/放弃操作；已完成且不再写入的预览不单独阻断。
- 删除在一个可回滚的本地事务中清除项目记录、当前文件、`Project.messages`、版本、候选、run、验证/恢复记录、资源索引及其他关联记录。事务失败时保留列表项、内存工作副本和可见错误，不以部分清除结果隐藏项目。
- 当前项目删除成功后清除当前项目指针并进入空白项目入口。旧标签页和迟到保存必须携带删除前的项目修订/写入者身份；仓储拒绝已删除身份的写入，不能静默复活项目。首版不增加回收站、云同步或后台恢复服务。
- 兼容已有 IndexedDB 数据：新增字段使用可选字段和明确默认值，缺少主会话标记的既有项目归入默认主会话；保留可读的消息、文件和历史版本，不伪造不存在的历史；不兼容或损坏记录显式报告。

**依赖与验收：** 复用现有 IndexedDB 保存和修订机制，首版仍是手动保存；对应 `R-PROJECT-03`、`R-PROJECT-04`、`R-MIGRATION-01`，验收条目为 `A-PROJECT-02`、`A-PROJECT-03`、`A-MIGRATION-01`，固定场景为 `UX-PROJECT-01`、`UX-MIGRATION-01`。F2 fixture、tsc、lint/build 已通过；删除故障、多标签、真实存量迁移和第五类故障未验证。

#### F3：版本栏、历史记录与恢复体验

**涉及现有模块：** 版本快照类型、`useProjectPersistence`、`ProjectManager`、工作台顶部项目栏、候选应用和历史恢复流程。

**实现范围：**

- 顶部持续展示项目名、自动递增的已接受版本号和保存状态；内部写入修订号保留在诊断中，普通 UI 不把它当作版本号。
- 已接受版本使用项目内自动递增的数字序列；可选版本名/备注是元数据。用户输入的 `1.0.0` 等文本只作标签，不参与 `versionId`、排序、hash 或恢复来源判断。
- 聊天卡片标明它关联的历史版本、当前已接受版本或未接受工作副本；普通 `chat` 不生成版本。没有已接受版本时显示“尚无已接受版本”，不显示 v0。
- 确认从 v2 恢复时直接创建新的恢复版本和工作副本；如果已有 v4，新的恢复版本为 v5，并保存 `restoredFrom=v2` 等来源元数据，v3/v4 仍可访问。恢复版本沿用被选快照，不继承或伪造新的运行校验通过证据；恢复后仍需显式手动保存本地项目快照，手改、格式化或手动保存工作副本不创建额外已接受版本。

**依赖与验收：** 依赖阶段 B/C 已有不可变版本和恢复记录，不改变快照/版本 ID 以重命名标签；对应 `R-VERSION-02`、`R-VERSION-03`，验收条目为 `A-VERSION-02`，固定场景为 `UX-VERSION-01`。F3 fixture、tsc、lint/build 已通过；完整版本栏、标签/备注和恢复浏览器现场未验证。

## 3. 必须明确的接口和数据约束

- 新增逻辑对象：`Project`、`WorkspaceSnapshot`、`VersionSnapshot`、`Candidate`、`RunRecord`、`ResourceManifest`、`ValidationReport`。
- 阶段 F 不新增通用 `Session`/thread 对象；一个 `Project` 的主会话继续使用现有 `Project.messages`。新增的主会话标记、版本标签/备注、删除保护和来源字段均应是可选且可迁移的元数据。
- `POST /api/chat` 增加可选的操作类型和编辑基线；缺省保持现有行为。编辑与修复必须携带 `runId`、当前文件和基线 hash。
- 操作类型由内部规则判定并保留在请求/诊断中，普通 UI 不暴露首次生成/当前代码修改的模式开关；edit 的消息上下文默认最多 6 条，当前编辑器快照和 hash 优先。
- 新增编辑流程事件及候选元数据；前后端同步扩展类型，旧的首次生成与普通聊天协议继续支持。
- 文件变更采用结构化操作列表，不解析自由文本 diff；拒绝重复路径、越界路径、不存在文件的删除和无效内容。
- hash 使用规范化路径、排序后的文件内容及资源 hash 计算 SHA-256；不静默改变源码换行或格式。
- 编辑请求默认最多 150 个文本文件，单文件 128 KiB、总源码 512 KiB；接口 JSON 上限 1 MiB，仅对相关接口放宽，并同步检查代理限制。超限明确拒绝，不截断代码。
- 本地项目资源默认单个最多 2 MiB、总量 10 MiB；不自动代理下载任意远程资源。资源缺失时禁止将包标为完整导出。
- 保存只记录必要消息、验证与运行摘要；不保存密钥，不把敏感完整请求写入公开案例。
- 删除项目必须在同一可回滚本地事务中处理文件、消息、版本、候选、run、验证/恢复记录和资源索引；事务失败保留项目列表项及工作副本，已删除项目的旧标签写入必须被拒绝。
- 版本号自动递增，显示标签/备注只能改元数据，不改变快照或 `versionId`；没有已接受版本时不显示 v0。
- 首版不支持 ZIP 导入、自动合并、云同步、自动保存或通用运行数据恢复。

这些数值是本计划选用的初始工程上限，不是测量结果；后续调整必须附带原因及对应验收变化。

## 4. 长任务交接与最终验收

真实模型运行统一通过脚本执行，提供两类明确命令：

- 生成并记录单个任务看板案例。
- 按固定次数执行评测并汇总已有结果。

脚本必须支持按运行 ID 读取已有产物，成功任务不重复请求。中断的模型请求记录为中断；重新执行是新尝试，不宣称从后端节点续跑。

代理可启动真实运行并持续查看进度。等待约 5 分钟仍未完成时，可以交接给用户；这只是代理交接阈值，不是后端任务超时。交接时必须说明：

- 当前进程是否仍在运行，避免用户重复启动。
- 可复制的命令、工作目录和输出目录。
- 成功及失败的识别方式。
- 完成后提供哪个运行 ID，才能继续固化和验收。

每阶段结束都由主代理亲自审查关键 diff，并运行针对性检查。最终验收包含：

- 前后端类型检查、构建、改动范围 lint。
- 保存事务、文件变更、基线冲突和状态处理测试。
- 阶段 F 的主会话路由、内部 generate/edit/chat 判定、最近 6 条 edit 上下文、项目重命名/删除保护、旧标签页写入拒绝、版本栏/恢复来源和 IndexedDB 迁移兼容测试；新场景按 `UX-SESSION-*`、`UX-PROJECT-*`、`UX-VERSION-*`、`UX-MIGRATION-*` 单独报告，不能并入 A–E 的历史 EVAL 分母。
- 桌面与 390px 移动端浏览器验证、键盘操作。
- 首页、案例、工作台直达、项目上下文、对话/预览/代码切换和所有新增状态。
- 导出包解压后的类型检查、构建和资源访问；原生 ZIP 下载由用户手动确认。
- 第五类 IndexedDB 故障场景由用户手动确认，代理 fixture 结果不能代替现场证据。
- 真实模型、固定交互和故障夹具结果分别记录。

长时间或环境阻断的检查可以交接手动执行，但对应项保持“未验证”，不据此宣布整阶段通过。

进入执行后，由 Luna 将本计划及阶段交接记录落到 `docs/phase-two-plan/`，维护需求—实现—验收对应关系。阶段 F 已按 F1/F2/F3 记录代码实现与 fixture/类型/构建证据；浏览器完整现场、真实聊天链路、移动端/键盘、ZIP 和 IndexedDB 第五类故障仍按未验证处理，只有现场证据产生后才更新相应状态。仅当实际核心功能或关键目录结构发生变化时更新 AGENTS.md，不写日常改动日志。
