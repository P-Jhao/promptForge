# 03 稳定需求

需求 ID 是后续设计、实现、验证和验收的共同索引。ID 一经采用不应因为实现文件或界面文案变化而重命名。优先级含义：P0 是第二阶段核心门槛，P1 是完整交付需要，P2 是未来评估或增强项。

本轮新增的 `R-SESSION-*`、`R-CONTEXT-01`、`R-PROJECT-03/04`、`R-VERSION-02/03` 和 `R-MIGRATION-01` 已由阶段 F1/F2/F3 落到代码，并由对应 fixture、前端 tsc、lint/build 检查；完整浏览器现场、真实聊天链路、移动端/键盘、ZIP 和 IndexedDB 第五类故障仍未验证。A–E 既有需求和历史证据保持原样。

## P0 需求

| ID | 需求 | 可核验结果 |
| --- | --- | --- |
| R-COVER-01 | 预置案例和导出项目的运行时资源必须有明确、可追踪的交付方式。引用的封面不应只存在于宿主应用的 `public` 目录而在案例文件映射中失去来源。 | 在案例 iframe、Sandpack 预览和解压后的导出项目中检查资源请求或文件清单；资源失败时给出可理解错误，不静默显示破图。 |
| R-PREVIEW-01 | 预览必须区分模板加载、沙盒启动、应用 ready、运行时错误、超时和不可用。只有真实的 ready 证据才能显示预览可用。 | 代码已经收到但沙盒仍启动时仍显示启动状态；ready 后不再显示旧的 waiting；失败或超时时显示原因和重试入口。 |
| R-CASE-01 | 第二阶段必须提供一个独立任务看板案例，身份、入口、文件、资源和摘要与小说案例分离。 | 从独立入口打开任务看板；检查 manifest/元数据和文件路径，不依赖小说 48 文件清单。 |
| R-CASE-02 | 任务看板案例必须由真实模型运行生成并在验收通过后固化；固化内容必须保留生成来源和验收证据。 | 能指出真实 run、输入需求、模型配置（不含密钥）、候选版本、验收记录和固化时间；本轮不接受 Mock 回放作为生成来源。 |
| R-PROJECT-01 | 用户可以保存项目工作副本，并在同一浏览器重新打开后恢复当前文件、项目身份、已接受版本和必要对话/运行元数据。 | 刷新或关闭后再次打开项目，恢复到保存时的文件和版本；未保存编辑不会被保存动作之外的状态更新覆盖。 |
| R-PROJECT-02 | 恢复必须保护未保存编辑，并能报告读取失败、写入失败、配额不足、版本不兼容和本地项目不可见等情况。若能检测到存储被清除，才说明这一事实；否则只能说明“未找到本地项目”并提示可能原因，不能断言是清站点数据。 | 恢复前检测 dirty 状态并让用户保留/放弃/另存；失败时不清空内存中的工作副本，界面给出可行动结果。关闭页面后内存不存在，不得承诺仍可恢复。 |
| R-SESSION-01 | 一个项目对应一个主会话；新建项目创建空白主会话，打开项目恢复该项目已保存的 `Project.messages`、当前文件、已接受版本和必要运行摘要，并在同一项目中继续聊天。 | 新建项目没有旧项目消息、文件或版本；重新打开同一项目后消息、代码和版本身份一致；不需要通用多会话/线程表。 |
| R-SESSION-02 | 普通 UI 不提供“首次生成/基于当前代码修改”的日常模式开关，但内部必须判定 `generate`、`edit`、`chat`：空项目生成，有代码且明确修改走 edit，解释讨论只走 chat 且不创建候选或版本，意图歧义先询问。 | 检查请求诊断中的 operation 和界面行为；聊天不改变文件/版本，歧义不覆盖当前文件，用户无需选择模式。 |
| R-SESSION-03 | 已有主会话提出另一个项目时，必须在创建独立项目主会话前确认；只能带入用户选择的背景消息或需求摘要，不能混用原项目的文件、工作副本、候选或版本身份。 | 取消确认时原项目不变；确认后新项目拥有独立 ID、空白或明确选择的起点，两个项目的消息、文件和版本可分别恢复。 |
| R-CONTEXT-01 | edit 请求的代码真相必须是发送时当前编辑器的完整快照（包含未保存编辑）及稳定 hash；历史消息只作辅助，edit 默认只使用最近 6 条 `Project.messages`，不能声称拥有完整会话记忆。 | 在请求记录中核对快照/hash 与编辑器内容一致；记录上下文窗口边界，超出窗口的消息不被默认为模型已知。 |
| R-VERSION-01 | 用户可以从已接受的历史版本选择恢复；恢复要保护 dirty 工作副本，用户确认后直接产生新的恢复版本和工作副本，不删除该历史版本之后的版本。恢复版本沿用被选快照，不继承或伪造新的运行校验通过证据。 | 选择旧版本后检查当前文件、来源版本、恢复版本和恢复记录；取消或冲突时原工作副本不变，后续版本仍可选择。 |
| R-PROJECT-03 | 项目列表必须提供重命名和删除入口；重命名只修改项目元数据，不改变 `projectId`、消息、文件或版本身份。 | 重命名后刷新/重开仍指向同一项目；项目列表可从明确入口发起删除并显示目标范围。 |
| R-PROJECT-04 | 删除项目必须明确并在一个可回滚本地事务中清除该项目的本地文件、消息、工作副本、版本、候选、run、验证/恢复记录、资源索引和其他关联记录。未保存、进行中生成/写入/验证/修复、候选存在或其他标签页占用时必须防误删；已完成且不再写入的预览不单独阻断。事务失败保留列表项和工作副本，当前项目成功删除后进入空白入口，旧标签写入不得复活项目。 | 逐项检查删除范围、保护分支、事务失败后的可见状态、当前项目空白入口和旧标签页写入被拒绝；不要求回收站、云同步或后台恢复。 |
| R-VERSION-02 | 顶部必须持续显示项目名、当前已接受版本和保存状态；普通 UI 隐藏内部 revision，仅在诊断中保留。历史版本、当前版本和未接受工作副本必须可区分；没有已接受版本时显示“尚无已接受版本”，不能显示 v0。 | 在空项目、已接受版本、dirty 和保存失败状态核对顶部信息与历史卡片；revision 不被误当作用户版本号。 |
| R-VERSION-03 | 已接受版本号按项目内自动递增；可选版本名/备注是元数据，手写 `1.0.0` 等标签不能改变版本 ID、排序、hash 或快照。用户确认恢复 v2 时直接形成新的恢复版本（已有 v4 时为 v5），记录来源并保留 v3/v4；手改/手动保存工作副本不创建已接受版本。 | 核对确认恢复后立即产生 v5 及来源记录、后续历史保留、标签修改和手动保存前后的 versionId/快照不变；恢复不伪造新的运行校验通过证据。 |
| R-MIGRATION-01 | 现有 IndexedDB 数据必须兼容迁移：新增字段使用可选字段和明确默认值，缺少主会话标记的既有项目归入默认主会话；保留可读的消息、文件和版本，不伪造不存在的历史；不兼容或损坏记录显式报告。 | 使用不带新增字段的旧记录验证主会话默认和内容保留；使用损坏/不兼容记录验证错误可见且不静默重置。 |
| R-EDIT-01 | 继续修改请求必须以当前编辑文件快照和明确的 base 版本/hash 为基线，而不是只发送文本 history 或最近一次生成版本。 | 手改任务看板标题后请求“增加优先级筛选”，新候选保留标题并增加筛选能力；请求和结果能追溯到同一个基线。 |
| R-CHANGE-01 | 新生成、修复或导入的结果必须先进入候选状态；只有通过约定校验并由用户明确确认应用后才成为当前结果。首版不自动接受候选。 | 候选失败、冲突或未验证时，当前已接受版本和当前编辑文件仍可查看、恢复和导出；没有用户确认不能创建已接受版本。 |
| R-CHANGE-02 | 基于旧 base 继续修改时必须检测并呈现冲突，禁止静默覆盖另一个标签页或本地更新后的工作副本。首版冲突不自动合并，须由用户显式重新基于当前内容请求或选择保留/放弃。 | base hash 不匹配时生成被阻止或进入冲突候选；用户能查看差异，并以最新文件重新请求；不能由安全合并判断替代确认。 |
| R-VALIDATE-01 | 每个候选结果必须经过分层校验：文件/协议完整性、静态类型或构建、沙盒启动和固定功能场景；各层结果分别记录。 | 验证报告列出通过、失败、跳过和未验证层级；SSE `done` 或代码可见不能替代运行校验。 |
| R-FIX-01 | 自动修复必须有界、可追踪、只作用于候选结果，并在每次修改后重新校验。上限包括至少次数、总时间、文件大小或资源范围，具体值在实现前确定。 | 每次修复记录原因、输入 base、改动文件、尝试序号和验证结果；到达上限后停止并保留失败候选供用户处理。 |
| R-EVAL-01 | 第二阶段必须用固定需求和固定验收条目比较生成、修改、恢复和失败恢复表现。 | 对每个固定场景记录输入版本、环境、结果、耗时口径、修复次数、保留性和未验证原因；不能只凭主观“看起来成功”。 |

## P1 需求

| ID | 需求 | 可核验结果 |
| --- | --- | --- |
| R-GEN-01 | 生成、验证、预览和保存状态必须互相独立，界面要说明当前能做什么。 | 生成完成但预览未 ready 时仍可查看代码和候选状态；模板错误不清除已有完整结果。 |
| R-FAIL-01 | 失败、EOF、超时、取消和重试要保留此前可用结果及必要的请求上下文，并区分客户端断开与上游终止。 | 失败后可以重试原始请求或从当前工作副本重新请求；界面不宣称模型已被彻底停止。 |
| R-EXPORT-01 | 导出默认读取当前编辑文件，包含被引用且有权限交付的资源，并在资源无法读取时阻止生成不完整包或明确标记缺失。 | 编辑后导出的文件与编辑器当前内容一致；ZIP 清单和资源引用可以互相核对。 |
| R-CASE-03 | 固化案例必须显示“真实生成后固化”的来源边界，预置回放不应伪装成当前新生成。 | 案例页和工作台文案能区分预置成果、真实 run 和用户自己的生成。 |
| R-A11Y-01 | 关键按钮、状态、错误、重试、取消、保存和冲突处理支持键盘操作、焦点反馈和屏幕阅读器语义。 | 不用鼠标完成三条固定场景的入口、编辑、保存和恢复；状态更新有可读文本。 |
| R-MOBILE-01 | 390px 左右窄屏仍能进入案例、切换对话/预览/代码、查看状态和执行保存/重试；代码和筛选区域不产生不可理解的横向溢出。 | 在固定移动端尺寸完成关键场景；必要的横向滚动仅出现在明确的表格/代码区域。 |
| R-SEC-01 | 项目、文件、资源和模型输出必须在路径、大小、内容和访问范围上受约束；提交的案例和环境示例不含密钥。 | 非法路径、过大文件或不允许的资源被拒绝并留痕；诊断信息不泄露密钥或完整敏感请求。 |

## 非目标

本阶段不包含：

- Vue 生成、Vue Sandpack 运行、Vue 项目保存或 Vue 自动修复；
- 通用多用户账号、云端项目库、权限系统、实时协作和跨设备同步；
- 通用多会话/线程架构；每个项目只维护一个主会话，跨项目需显式创建独立项目；
- 无限次数的自主模型修复，或在未按接受策略确认时直接覆盖工作副本；
- 面向用户的“首次生成/基于当前代码修改”模式开关；操作分类保留为内部请求语义；
- 任意第三方资源代理、素材版权管理和完整部署平台；
- 对已有小说案例进行新的模型生成以冒充任务看板案例；
- 让所有生成应用的运行时内存数据自动跨刷新恢复；
- 以“客户端收到事件”“代码能打开”或“ZIP 已下载”代替真实运行和功能验收。
