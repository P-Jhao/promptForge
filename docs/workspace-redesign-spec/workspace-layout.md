# 工作台布局与操作映射

状态：规划稿。本文定义目标区域职责和可操作行为，不表示当前 `AppShell` 已经达到目标布局。

## 视觉和尺寸基线

参考图只用于确认“顶部项目栏 + 左对话栏 + 右预览/代码区”的视觉关系。视觉约束是浅灰蓝底、白色面板、蓝紫强调色、细边框和轻阴影，项目顶栏保持紧凑；不仿造浏览器三色窗口按钮，也不添加虚假头像、账户/套餐入口。宿主不复制图中的客户表格、业务导航或详情抽屉；这些内容只能出现在案例自身的预览应用里。

桌面基线如下：

| 区域 | 目标行为 | 约束 |
| --- | --- | --- |
| 顶部项目栏 | 单行固定在工作台顶部；项目身份和全局项目动作集中在此 | Logo、项目名/切换、版本/保存状态、手动保存、唯一主导出、更多操作均应可见或在明确菜单内可达；不放浏览器三色窗口按钮、虚假头像、账户/套餐/模型选择 |
| 左对话栏 | 桌面固定窄栏，约 340–380px；消息区独立滚动，输入区固定在底部 | 只保留一个输入框；阶段、耗时、候选摘要和错误不能挤出输入框；不把案例业务导航放入此栏 |
| 右内容区 | 占剩余宽度和高度；预览、代码由同一 `viewMode` 控制 | 工具栏不覆盖可交互内容；代码文件树和编辑器保持可滚动；预览使用真实 ready/错误状态 |
| 桌面 1440px | 作为主要验收视口 | 左栏保持目标范围，右栏足以显示案例和工具栏；不得出现横向滚动或按钮被挤入不可见区域 |
| 桌面 1280px | 作为紧凑桌面验收视口 | 项目栏和工具栏仍可操作；必要时文字收缩到有意义的标签/提示，但不隐藏核心动作 |
| 窄屏降级 | 延续当前 chat/preview 面板切换和可滚动布局 | 只做防回归；不新增设备模拟、缩放、移动端专项导航或独立移动设计系统 |

当前 `AppShell.tsx` 已把左栏写为 `sm:w-[400px]`，并在小屏显示“对话与进度/预览与代码”切换；这是一项现状证据，不是目标尺寸或已通过 1440/1280 验收的证明。后续实现可以调整布局容器，但不能移除窄屏降级。

## 区域与操作映射

### 顶部项目栏

| 目标控件 | 用户动作 | 复用的现有能力/证据 | 目标语义 |
| --- | --- | --- | --- |
| PromptForge Logo | 返回首页 | `AppShell.tsx` 的 `/` 链接 | 保留首页返回，不把首页导航扩展为业务导航 |
| 项目名/切换 | 查看项目列表、打开项目；必要时在 dirty/运行中状态先处理保护 | `ProjectManager`、`ProjectBrowserModal`、`useProjectPersistence.openProject` | 一个项目对应一个主会话；切换后恢复该项目消息、工作副本和版本，不混用上下文 |
| 项目名编辑 | 重命名当前项目 | `renameProject` 与现有 rename dialog | 只改元数据，不改 `projectId`、消息、文件和版本；需保留错误反馈 |
| 版本/保存状态 | 查看当前已接受版本和是否未保存 | `acceptedVersion`/版本序列、`persistence.dirty`、`storageStatusLabel` | 无已接受版本显示“尚无已接受版本”；手动保存后显示已保存；不把诊断修订号当版本号 |
| 保存 | 显式保存当前工作副本 | `saveCurrentProject` | 保存包含当前编辑器文件、消息、版本和必要运行摘要；失败保留内存内容和 dirty 状态，不自动重试/自动保存 |
| 导出 | 导出明确标注的对象 | `downloadGeneratedCode`、`PreviewToolbar` | 预置案例导出 `previewFiles`/manifest；项目导出当前工作副本，不能默认说是已接受版本；候选不因预览而覆盖导出 |
| 更多项目操作 | 新建、另存为、版本历史、重命名、删除等 | 现有按钮、`ProjectBrowserModal`、mutation dialogs | 菜单只收拢已有项目语义，不新增分享、账号、模型或云同步 |

顶部项目栏不显示“自动保存中”。保存状态只在用户触发保存、打开、另存为、恢复或仓储返回结果后变化；预览编译、输入文字和浏览案例不会被写成保存成功。

### 左对话栏

| 区域 | 目标行为 | 现有代码事实 | 保留/改进要求 |
| --- | --- | --- | --- |
| 会话头部 | 说明当前项目和输入用途，提供必要案例入口 | `ChatPanel` 现有介绍和“看案例”链接 | 文案可以收紧；案例入口只指向已注册或明确标记为规划的入口 |
| 阶段状态 | 显示正在生成/回复、当前阶段/步骤、已完成步骤和客户端耗时 | `GenerationStatusPanel` | 进行中的阶段附着本次 assistant 回复；完成后可收起为摘要，不要求为历史持久化新增完整阶段事件；“耗时”必须标注客户端接收间隔（含网络）或用户总等待，不伪造服务端节点耗时 |
| 消息区 | 显示用户消息、assistant 文本、阶段历史和版本关联卡片 | `useChat`、`Project.messages`、`ThoughtChain`、`VersionCard` | 消息历史与版本历史在语义上分开；聊天不创建版本；长消息和阶段信息只能在消息区滚动 |
| 候选区 | 在消息或状态附近显示候选摘要、基线、变更、L0–L5 和动作 | `CandidatePanel` | 保留查看变更路径、尝试修复、应用、放弃；候选没有通过 required 校验或基线冲突时不能应用 |
| 输入区 | 底部固定一个 `Sender`，支持提交和执行中取消 | `ChatPanel` 的 `Sender` | 不新增第二个输入框、生成/编辑模式切换或附件上传；候选/执行/保存保护时给出可理解禁用原因 |
| 示例/真实来源提示 | 让用户知道预置成果不会伪生成，真实请求可能耗时或失败 | `MockModeToggle` 和底部边界文案 | 可保留为来源提示；它不是用户选择 generate/edit/chat 的模式开关 |

### 右预览/代码区

工具栏的目标控件及状态如下：

| 控件 | 预览视图 | 代码视图 | 约束 |
| --- | --- | --- | --- |
| 预览/代码切换 | 当前态 | 当前态 | 复用现有 `viewMode`，目标位置在右侧区域内，移动端降级仍可用 |
| 刷新 | 调用现有 Sandpack refresh/retry 语义 | 可保持当前文件和编辑内容，不重置项目 | 只重新运行预览，不清除消息、候选、工作副本或版本；错误时保留错误原因和重试入口 |
| 全屏/退出全屏 | 扩大右区，保留返回工作台动作 | 同样适用 | 不改变项目、候选、保存状态；工具栏和焦点必须仍可达 |
| 导出（可复用） | 可复用顶部唯一主导出动作，并显示当前案例/当前工作副本/候选隔离提示 | 执行同一下载动作 | 右栏不强制重复放置导出按钮；若复用必须使用同一对象标签和语义，不默认宣称已接受版本、离线可用或 ZIP 已通过构建 |
| 更多预览动作 | 原则上不增加 | 原则上不增加 | 不放设备切换、宽高预设、缩放滑块、分享或模型控制 |

当前 `PreviewToolbar` 只有在代码视图显示下载按钮，并提供全屏；`SandpackPreview` 自带刷新按钮，`SandpackView` 另有重试函数和构建/挂载/运行错误覆盖层。目标是让刷新在右侧有清楚归属，并由顶部提供唯一主导出；右侧若复用下载动作，必须复用同一对象标签和语义，避免重复入口或另造一套运行状态。

## 导出对象映射

导出必须在按钮旁或下载前的可访问标签中表达对象。对象按工作台上下文解释：

1. **预置案例上下文**：使用 `previewFiles` 和 `previewManifest`。这些文件是预组装展示成果，不属于当前项目工作副本；远程资源只在 manifest 中记录 URL 和边界。
2. **普通项目上下文**：优先使用 `currentFiles`，因为它包含用户当前编辑器中的手改内容；没有当前文件时才回退到 `generatedFiles`。标签应写“当前工作副本/含未保存修改”（如适用），不能写“已接受版本”。
3. **候选上下文**：候选在右侧可预览，但默认项目导出动作不得读取候选文件。若未来提供候选下载，必须是显式写明候选 ID 的动作，且下载不等于应用、保存或版本接受。
4. **历史版本**：从版本历史中恢复或导出时，必须由用户明确选定版本；不能因为顶部显示 v4 就把普通导出静默替换成 v4。

模板文件可以按既有下载工具作为补充，但不能将模板、预览展示文件和当前项目文件混写成一个没有来源说明的包。

## 焦点、滚动与遮挡规则

默认 Tab 顺序为：Logo/首页 → 项目名/项目切换 → 版本/状态可读信息 → 保存 → 导出 → 更多 → 左栏可见消息操作/候选操作 → 底部输入框与取消 → 右侧视图/刷新/全屏/代码编辑器。具体 DOM 顺序可以调整，但必须满足以下行为：

- 键盘可到达保存、切换、导出、刷新、全屏、应用、放弃、重试和取消；禁用动作有 `disabled` 或可读状态说明，不靠颜色区分。
- 对话框打开后焦点进入对话框，Escape/取消关闭后回到触发控件；保存/放弃/取消选择不能让焦点跳到页面顶部。
- 左消息区和代码编辑器可以独立滚动；滚动消息不能把底部输入框推出可见工作区。
- 右侧工具栏浮层不覆盖案例第一屏的主要操作、代码标签或错误按钮；预览错误、加载和候选提示要留出安全区。
- 1440px 和 1280px 下不出现横向滚动；窄屏只切换面板，不新增第三套布局行为。

## 布局状态边界

| 状态 | 左栏 | 顶部 | 右栏 | 不允许的隐式动作 |
| --- | --- | --- | --- | --- |
| 空白项目 | 空消息提示、单一输入框、无已接受版本 | 显示“尚无已接受版本 · 未保存” | 模板/预览等待或空态 | 不伪造消息、版本、运行结果或保存成功 |
| 执行中 | 当前阶段、已完成步骤、实时客户端间隔、取消 | 保存/切换按保护规则禁用或提示 | 保留旧画面或显示启动状态 | 不覆盖当前文件，不声称服务端已结束 |
| 候选待校验/待应用 | CandidatePanel 展示基线、变更和分层校验 | 导出/切换遵守候选隔离 | 候选可独立预览 | 不把候选写入 currentFiles、版本或普通项目导出 |
| 失败/超时 | 错误位置、错误类别、重试入口 | 保留 dirty/版本状态 | 预览保留画面或给出重试原因 | 不用失败结果覆盖旧工作副本，不把 timeout 当代码失败 |
| 已取消 | 停止接收说明、已收到结果是否保留 | 保存状态不被取消伪造为已保存 | 保留旧预览；取消前已有候选按既有逻辑隔离 | 不承诺供应商调用已完全终止；只忽略迟到结果，不创建迟到候选 |
| 保存失败 | 错误和可行动重试/另存为提示 | 仍显示未保存 | 当前预览和编辑器内容保留 | 不清空内存、不回退到旧版本、不自动重试 |
| 切换/恢复 | 先处理进行中、候选和 dirty 分支 | 清楚显示目标项目/版本 | 只载入目标项目或目标候选 | 不混用消息、文件、版本；不静默放弃编辑 |
