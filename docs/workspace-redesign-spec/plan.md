# PromptForge 工作台重设计执行计划

## 1. 目标与实施约束

依据 `docs/workspace-redesign-spec/` 四份规格，把工作台调整为参考图的“顶部项目栏＋左侧对话＋右侧预览”，新增客户管理后台、数据分析看板、个人博客三个可操作案例。

- 只提供桌面预览，不添加设备切换或缩放；保留现有窄屏降级。
- 复用生成、聊天、候选、保存和版本机制，不新增后端 API、存储 schema 或宿主依赖。
- 首页只同步案例入口与必要文案，不进行视觉重构。
- 不覆盖现有未提交修改，不自动提交 Git。
- 每次上下文压缩后，重新读取本计划、根目录 AGENTS.md，以及当前阶段对应的 spec。

全部代码与文档修改由一个子代理执行，创建参数明确指定：

```text
model: gpt-5.6-luna
reasoning_effort: max
fork_turns: "1"
```

明确告知其已经是子代理，不得继续创建子代理。主代理负责分析、审查、检查和浏览器验收；发现问题交回同一子代理修正。

## 2. 阶段一：重构工作台外壳

**布局与视觉**

- 使用浅灰蓝背景、白色面板、蓝紫强调色、细边框和轻阴影。
- 顶栏高度以 64px 为基线；左侧对话栏宽 360px，右侧占剩余空间。
- 消息区域独立滚动，单一输入框固定在左栏底部；进度和候选不能把输入框挤出视口。
- 右侧工具栏占独立布局空间，不覆盖案例、编辑器或错误反馈。
- 使用工作台范围的 CSS Module；保留 Tailwind 全局入口，避免影响首页及案例内部样式。

**操作归属**

- 顶栏：Logo、项目名称与切换、已接受版本、保存状态、保存、主导出按钮、更多菜单。
- 项目切换器复用现有项目列表；更多菜单固定收纳新建、另存为、版本历史、重命名、删除。
- 右侧：预览／代码、刷新、全屏／退出全屏；不重复设置主导出按钮。
- 保留现有项目切换、未保存修改、运行中与候选保护，不另写一套项目状态管理。

**阶段完成条件**

先使用现有小说和任务看板验证新外壳。主代理检查 1440px、1280px 布局、焦点、滚动及项目操作，再进入后续阶段。

## 3. 阶段二：整理对话、反馈与导出

- 将本次执行状态放到对应回复附近；执行中展开，结束后可收起摘要，不增加完整阶段事件持久化。
- 保留内部生成／编辑／聊天判定；普通聊天只追加消息，不生成版本。
- 候选展示摘要和主要动作，变更路径与技术诊断可展开；保留校验、冲突、修复、应用和放弃限制。
- 显示实际客户端等待时间及计时口径，不使用虚构百分比或预计耗时。
- 请求重试沿用原请求语义；刷新仅重新运行预览，不调用模型或新建模型运行记录。
- 顶部导出明确区分“当前案例”和“当前工作副本”；工作副本包含未保存编辑时给予标识。候选预览不改变普通导出对象。
- 复用现有下载工具，提取供顶栏调用的文件选择逻辑；无文件时禁用，不增加历史版本或候选专用导出功能。

**检查重点**

对导出对象选择、候选隔离及受影响的状态保护补充必要单元或集成检查；静态布局不新增镜像测试。

## 4. 阶段三：制作并接入三个案例

**制作方式**

串行制作客户管理后台、数据分析看板、个人博客。通过当前真实生成链路取得初始成果，保留需求、运行记录及原始输出；必要人工修正由 Luna 完成并逐项记录。

复用现有 recorder、案例组装及来源校验工具的公共能力。新增案例记录独立保存，不混入既有任务看板评测结果，不重跑完整历史评测。

**固定范围**

| 案例 ID                    | 必须实现的交互                                               |
| -------------------------- | ------------------------------------------------------------ |
| `customer-management-demo` | 搜索、状态筛选、新增与必填校验、编辑、详情抽屉；新增后可搜索，编辑后列表与详情同步 |
| `analytics-dashboard-demo` | 固定演示数据的指标、趋势、分类图；日期范围变化后统一重新计算，并支持无数据状态 |
| `personal-blog-demo`       | 文章列表、分类、搜索、详情、返回列表和明暗阅读主题           |

案例使用合成数据；客户新增编辑只保留当前演示运行内存，刷新可重置并明确提示。图表优先使用现有依赖或轻量 SVG，不新增宿主图表库。图片若使用远程 URL，必须记录来源并验证加载与失败表现。

**接入与兼容**

- 使用轻量案例注册表统一案例元数据和文件加载入口，按选中案例加载文件，避免三个成果全部进入初始包。
- 三个新案例分别具有来源记录、资源清单、静态成果和验收记录。
- 每个案例经过主代理目标工作台浏览器交互验证后，才进入默认示例列表。
- 工作台提供三个直接入口；首页现有案例区域同步三项成果和真实来源说明。
- 保留小说 library／notes 与 `task-board-real-eval` 旧 URL，不删除旧项目。
- 打开示例不发送模型请求、不覆盖当前项目；当前存在未保存内容或候选时沿用保护流程。

生成失败时保留记录，由主代理分析原因后决定修正方式；不反复盲试、不用手写页面冒充未经修改的模型成果。

## 5. 验收与交付

**自动检查**

- 前端 TypeScript、改动范围 ESLint、生产构建、`git diff --check`。
- 新旧案例的组装一致性、来源记录与资源引用检查。
- 与此次调整有关的导出、候选和项目状态单元／集成检查。
- 不新增 Playwright E2E。

**主代理浏览器验收**

- 1440px、1280px 桌面：布局、独立滚动、输入框固定、无横向溢出及工具栏遮挡。
- Tab 焦点、菜单关闭与焦点恢复、候选主要动作、全屏退出。
- 新建、打开、手动保存、版本历史与恢复的关键回归。
- 至少一次真实修改请求：候选预览、应用或放弃、版本与保存状态符合现有契约。
- 三个新案例完成表中关键交互；旧案例链接仍可打开；示例打开期间不调用 `/api/chat`。
- 现有窄屏布局做一次防回归检查，不开展移动端专项改版。

**记录与人工交接**

实施记录放入 `docs/workspace-redesign-spec/`，同步当前实现状态、来源、检查结果和未验证项。AGENTS.md 仅在核心边界或关键目录确实改变时更新。

原生 ZIP 下载、解压后运行，以及耗时较长或环境阻断的故障场景，可交给用户手动验证；列明操作步骤和预期结果。未执行项保持“未验证”，不能据此宣称全部通过。
