## 案例内交互

### 客户管理后台：`customer-management-demo`

案例应用内提供一份合成客户数据表，用户可以：

- 按姓名、公司或标签搜索；
- 按明确的数据状态、客户分组或来源筛选；
- 打开“新增客户”表单，检查必填字段，成功后把新记录放入当前内存数据；
- 从列表打开编辑表单，修改后回到列表并保留筛选语义；
- 打开详情抽屉，查看摘要、标签、联系记录等固定字段，并能关闭抽屉回到列表。

表格、筛选、表单、详情抽屉和案例内部业务导航都属于案例源码。宿主工作台只显示项目栏、对话、预览/代码工具栏和状态，不把客户分组或详情抽屉变成宿主菜单。

### 数据分析看板：`analytics-dashboard-demo`

案例应用内提供固定的指标卡、趋势图、分类图和日期筛选。日期范围变化时，指标、趋势和分类视图必须依据同一份固定演示数据联动更新，显示空结果或无数据时有明确状态。筛选交互可以是本地计算；不要求真实数据库、流式数据、权限或后台计算。

### 个人博客：`personal-blog-demo`

案例应用内提供虚构文章列表、精选文章、作者资料、分类筛选、关键词/标签搜索、文章详情、阅读主题切换和订阅反馈。列表到详情、返回、空结果、主题切换、搜索清除和订阅提示应保持可操作；不扩展文章编辑、发布、评论、权限、媒体上传或完整 CMS 后端。

## 真实生成、固化和静态打开

三份案例必须沿用现有真实生成链路产出，不能用 Mock 回放、手写“已生成”标记或截图制造来源。每份案例需要能追溯以下信息：

- 原始输入需求、真实 run ID、模型配置摘要（不含密钥）、SSE/文件产物位置和生成终态；
- 候选版本、校验报告、人工修正的文件路径/原因/来源，不能改写原始产物来掩盖失败；
- 使用的合成数据说明、资源 URL/许可或本地资源来源、固化时间和静态文件生成命令；
- 最终案例与来源文件的对应关系，能够从 descriptor、manifest 和 provenance 互相核对。

固化后的预组装案例通过静态文件 map 和 manifest 打开，不能因为用户点开示例而重新调用模型、刷新真实生成链路或污染当前项目。静态打开也不等于 Sandpack ready、导出构建或离线可用；这些仍按验收文档分别记录。

## 资源、远程边界和导出

- 客户数据绝不能借用真实联系人。姓名、邮箱、电话、公司、地址和头像均使用可识别为演示的合成值；资源许可要写清楚。
- 远程资源必须在 manifest 中声明 URL、类型、用途、是否必需、来源和许可。宿主或案例检查失败时显示具体资源失败原因和重试/降级边界。
- 远程图片或字体的 URL 不等于已下载到导出包。导出可以保留 URL 元数据；只有经过明确构建和资源检查后才能报告对应资源可用。离线访问默认标为不可用/未验证。
- 预置案例的导出对象是 `previewFiles` 和对应 manifest；项目导出对象是当前工作副本（`currentFiles` 优先），不得默认替换为已接受版本。候选预览不能静默进入普通导出。
- 原生 ZIP 下载是否完成、下载耗时、解压后的网络请求和导出构建由用户手动确认；代理的文件生成、静态检查和代码检查不能代替这些浏览器/操作系统证据。
